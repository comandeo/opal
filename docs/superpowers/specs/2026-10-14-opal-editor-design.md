# Opal — минималистичный Markdown-редактор

Дата: 2026-10-14. Статус: черновик, ждёт согласования раздела 2.

## 1. Цель

Редактор для письма прозы в духе Typora: Markdown-разметка отображается
оформленным текстом прямо при наборе. Без Electron и без веб-движков вообще.
Главное — лёгкость, скорость, простота: мгновенный запуск и отзывчивость,
как у приложений «старых времён». Работает в Linux (сейчас — sway/Wayland),
переносим на FreeBSD.

## 2. Поведение (раздел для согласования)

### 2.1 Отображение: гибридный режим

- Текст оформлен: **жирный** — жирным, *курсив* — курсивом, заголовки —
  крупнее и т.д. Символы разметки (`**`, `_`, `#`, `` ` ``, `[…](…)`)
  скрыты.
- Разметка становится видна (бледным цветом) только у элемента под курсором,
  как в Typora. Если курсор во вложенном элементе (курсив внутри жирного) —
  раскрываются оба. Курсор вплотную к границе элемента тоже его раскрывает —
  иначе до разметки не добраться стрелками.
- При раскрытии текст сдвигается на ширину появившихся символов — так же,
  как в Typora.
- Для строчных блоков (заголовок, пункт списка, цитата, линия) «элемент» —
  это строка: разметка видна, когда курсор на ней. Для блока кода — весь блок.
- Если выделен фрагмент текста — раскрываются все элементы, которые он
  задевает.

### 2.2 Поддерживаемые элементы

Внутри строки:

| Разметка | Вид без курсора |
|---|---|
| `**жирный**`, `__жирный__` | жирный |
| `*курсив*`, `_курсив_` | курсив |
| `***оба***` | жирный курсив |
| `~~зачёркнутый~~` | зачёркнутый |
| `` `код` `` | моноширинный шрифт, фон |
| `[текст](url)` | подчёркнутый текст ссылки; Ctrl+клик открывает url |
| `<https://…>` | подчёркнутый url; Ctrl+клик открывает |

Блоки:

| Разметка | Вид без курсора |
|---|---|
| `#` … `######`, заголовки с подчёркиванием `===`/`---` | крупнее и жирнее, `#` скрыт |
| `> цитата` | вертикальная полоса слева, отступ |
| `- пункт`, `* пункт`, `+ пункт` | `•` вместо маркера |
| `1. пункт` | номер виден всегда, как обычный текст |
| `- [ ] задача`, `- [x] задача` | ☐ / ☑; клик по значку переключает |
| ```` ``` ```` блок кода, блок с отступом 4 пробела | моноширинный шрифт, фон; ограничители скрыты |
| `---`, `***`, `___` | горизонтальная линия |

Всё остальное (картинки, таблицы, формулы, сноски, HTML, YAML-шапка,
экранирование `\*`) — обычный текст без особого оформления.

### 2.3 Колонка

- Текст — в колонке по центру окна. Ширина задаётся в конфиге в символах
  (по умолчанию 70).
- Если окно уже колонки — текст занимает всё окно с небольшими полями.

### 2.4 Typewriter mode

- Строка с курсором всегда по центру экрана по вертикали — включая начало
  документа (над первой строкой — полэкрана пустого места) и конец.
- Прокрутка мгновенная, без анимации.
- Колесо мыши прокручивает свободно; при следующем движении курсора или
  наборе строка снова встаёт по центру.
- `Ctrl+T` включает/выключает режим до закрытия окна. Состояние при запуске
  берётся из конфига.
- Остальной текст не затемняется.

### 2.5 Файлы и сохранение

- `opal файл.md` — открыть файл. Если файла нет — он будет создан при первом
  сохранении. `opal` без аргументов — пустой документ без имени.
- Одно окно — один документ. `Ctrl+O` (диалог открытия) и `Ctrl+N` (новый
  пустой документ) заменяют документ в текущем окне, предварительно
  сохранив его.
- **Автосохранение:** через 1 секунду после паузы в наборе, а также при
  закрытии окна, `Ctrl+O` и `Ctrl+N`. `Ctrl+S` сохраняет сразу.
- Документ без имени не сохраняется автоматически, пока не задано имя:
  первый `Ctrl+S` открывает диалог выбора пути. Если непустой документ без
  имени закрывается или заменяется (`Ctrl+O`, `Ctrl+N`), редактор
  спрашивает: сохранить / не сохранять / отмена.
- Сохранение безопасное: оборванная запись (сбой, нехватка места) не портит
  файл на диске.
- Редактор не переформатирует текст: в файл попадает ровно то, что набрано.
- Если файл изменила другая программа, автосохранение его не перезаписывает,
  а спрашивает: загрузить версию с диска или перезаписать своей.
- Если сохранить не удалось (нет прав, диск полон) — сообщение об ошибке;
  в заголовке окна — признак несохранённых изменений `•`.
- Только UTF-8. Файл в другой кодировке не открывается, с понятным
  сообщением.

### 2.6 Окно и управление

- Никаких меню, панелей, вкладок, боковых панелей, строки состояния.
- Заголовок окна: `имя.md — opal` (или `Без имени — opal`).
- Клавиши: `Ctrl+S`, `Ctrl+O`, `Ctrl+N`, `Ctrl+T`, `Ctrl+Q`; плюс стандартные
  клавиши редактирования (`Ctrl+Z`/`Ctrl+Shift+Z`, копирование, выделение).

### 2.7 Конфиг

Файл `~/.config/opal/config` (или `$XDG_CONFIG_HOME/opal/config`).
Редактор его только читает; если файла нет — значения по умолчанию.

```
# ширина колонки в символах
column_width = 70
# основной шрифт и шрифт для кода (формат: семейство размер)
font = Serif 14
mono_font = Monospace 12
# typewriter mode при запуске
typewriter = true
# light | dark
theme = light
```

Ошибка в строке конфига — предупреждение в терминал, для этого параметра
берётся значение по умолчанию; редактор всё равно запускается.

### 2.8 Не делаем (в первой версии)

Картинки в тексте, таблицы с выравниванием, подсветка кода, формулы,
сноски, экспорт (HTML/PDF), **поиск и замена**, **проверка орфографии**,
подсчёт слов, focus mode (затемнение), настройки в интерфейсе, горячие
клавиши ширины колонки и размера шрифта, вкладки и несколько документов
в окне, боковая панель с файлами.

### 2.9 Критерии успеха

Замеряются на машине пользователя:

- окно с открытым файлом появляется быстрее ~200 мс от запуска;
- нет заметной задержки при наборе в документе на 100 КБ (обновление
  оформления — не больше 5 мс на нажатие);
- потребление памяти не больше ~60 МБ;
- в коде нет ничего Linux-специфичного: собирается на FreeBSD из портов.

## 3. Техническое устройство

### 3.1 Стек

- Rust (edition 2024), GTK4 через `gtk4-rs` (минимум GTK 4.10 — нужны
  `FileDialog`, `AlertDialog`, `UriLauncher`).
- Разбор Markdown — `pulldown-cmark` (без feature `html`; включены
  `ENABLE_STRIKETHROUGH`, `ENABLE_TASKLISTS`): даёт байтовые диапазоны для
  каждого события (`into_offset_iter`).
- Других зависимостей во время выполнения нет. Конфиг разбирается своим
  кодом. Для тестов допустима dev-зависимость `tempfile`.
- Сборка: Debian — `libgtk-4-dev`, `pkg-config`; FreeBSD — `gtk4`, `rust`,
  `pkgconf`.

### 3.2 Модули

```
src/
  main.rs      разбор аргументов, загрузка конфига, запуск GtkApplication
  config.rs    чтение и разбор конфига                         ┐
  markdown.rs  текст → Vec<Element>                            │ без GTK,
  reveal.rs    (элементы, курсор/выделение) → видимые маркеры  │ unit-тесты
  layout.rs    поля колонки и typewriter-отступы               │
  document.rs  загрузка, атомарное сохранение, внешние правки  ┘
  editor.rs    подкласс GtkTextView: теги, скрытие маркеров, отрисовка
               декораций, перевод байтовых позиций в символьные
  window.rs    окно, действия и клавиши, таймер автосохранения, диалоги
```

Вся логика — в модулях без GTK; `editor.rs` и `window.rs` — тонкая обвязка.

### 3.3 Модель элементов

```rust
pub struct Element {
    pub kind: Kind,            // Strong, Emphasis, Strike, Code, Link{url},
                               // Autolink{url}, Heading(u8), Quote,
                               // ListItem{ordered}, Task{checked},
                               // CodeBlock, Rule
    pub range: Range<usize>,   // байты исходного текста, к которым
                               // применяется оформление
    pub markers: Vec<Marker>,
}

pub struct Marker {
    pub range: Range<usize>,   // байты символов разметки
    pub scope: Range<usize>,   // где должен быть курсор, чтобы маркер
                               // был виден
}
```

Правила построения маркеров:

- Строчные элементы (`Strong`, `Emphasis`, `Strike`, `Code`, `Autolink`):
  открывающий и закрывающий разделители (длина по фактической серии
  символов `*`/`_`/`~`/`` ` ``), `scope` = `range` элемента.
- `Link`: `[` и хвост от `]` до конца элемента (`](url "title")` или `][ref]`);
  начало хвоста — конец последнего дочернего события. `scope` = `range`.
- `Heading`: ATX — префикс `#…# ` и необязательная закрывающая серия `#`;
  setext — строка подчёркивания. `scope` = весь заголовок.
- `Quote`: на каждой строке — свой маркер `>` (+ один пробел), по одному на
  уровень вложенности; `scope` = эта строка. Строки «ленивого продолжения»
  без `>` маркеров не имеют.
- `ListItem` (маркированный): маркер `-`/`*`/`+` с пробелом, `scope` =
  первая строка пункта. Нумерованные пункты маркеров не имеют (номер всегда
  виден).
- `Task`: один маркер на всё `- [ ] `, `scope` = первая строка.
- `CodeBlock` (огороженный): строки открывающего и закрывающего
  ограничителя целиком, включая перевод строки; `scope` = весь блок.
  Блок с отступом — без маркеров.
- `Rule`: вся строка, `scope` = строка.
- Незакрытая разметка (`**без пары`) не образует элемента — это обычный
  текст (так решает парсер CommonMark).

Видимость (`reveal.rs`): маркер виден, если отрезок курсора/выделения
`[min, max]` пересекается со `scope` включительно с обеих сторон
(`scope.start <= max && min <= scope.end`).

### 3.4 Поток данных

1. Сигнал `changed` буфера → текст целиком (`include_hidden_chars = true`)
   → `markdown::parse`.
2. Сравнение с предыдущим разбором по блокам верхнего уровня (диапазон +
   хеш содержимого); теги снимаются и ставятся заново только в диапазоне
   изменившихся блоков. Изменение, перестраивающее хвост документа
   (например, открытая ```` ``` ````), даёт пересчёт до конца — это редко.
3. После разбора и при `mark-set` для `insert`/`selection_bound` —
   `reveal::visible_markers`; тег `hidden` переключается только у маркеров,
   чей статус изменился.
4. Перевод байт → символы: один проход по тексту с отсортированными
   границами при каждом разборе; живёт в `editor.rs`, покрыт тестами на
   кириллице.
5. `changed` перезапускает одноразовый таймер автосохранения (1 с,
   `glib::timeout_add_local_once`).

### 3.5 Отображение в GTK

- Теги: `strong`, `em`, `strike`, `code`, `link`, `h1`…`h6` (scale 1.8 /
  1.5 / 1.25 / 1.1 / 1.0 / 1.0, все жирные), `quote` (левый отступ),
  `list-item` (левый отступ под `•`), `codeblock` (моноширинный,
  `paragraph-background`), `markup` (бледный цвет — у всех маркеров
  постоянно), `hidden` (`invisible = true`).
- Декорации рисуются в `snapshot_layer` подкласса GtkTextView поверх или
  под текстом, с координатами из `get_iter_location`: полоса цитаты,
  горизонтальная линия, `•` для пунктов, ☐/☑ для задач. Рисуются только
  у элементов в видимой области и только когда маркер скрыт.
- Клик по ☐/☑ — правка буфера `[ ]` ↔ `[x]` (попадает в undo как обычная
  правка). Ctrl+клик по ссылке — `gtk::UriLauncher`.
- Undo/redo — встроенная история GtkTextBuffer; программные изменения
  тегов в историю не попадают (проверяется в прототипе).
- Тема: `gtk-application-prefer-dark-theme` + две палитры цветов тегов.

### 3.6 Колонка и typewriter

- Ширина символа — `approximate_char_width` из метрик Pango для основного
  шрифта; ширина колонки = `column_width × ширина символа`.
- Боковые поля = `max(16 px, (ширина вида − колонка) / 2)`; пересчёт при
  изменении размера (переопределённый `size_allocate`, установка полей —
  через idle, чтобы не уйти в цикл перекомпоновки).
- Typewriter: верхнее и нижнее поля = `высота вида / 2 − высота строки / 2`;
  после каждого движения курсора/правки (в idle, после перекомпоновки) —
  `scroll_to_mark(insert, 0.0, true, 0.0, 0.5)`. Без режима — поля по
  две строки.
- Расчёты полей — чистые функции в `layout.rs`.

### 3.7 Документ и сохранение

- Загрузка: чтение байт, проверка UTF-8 (`String::from_utf8`), запоминание
  `(mtime, size)`. Переводы строк не трогаются (GtkTextBuffer хранит `\r\n`
  как есть; Enter вставляет `\n`).
- Путь канонизируется при открытии (символьные ссылки разыменовываются),
  чтобы запись шла в целевой файл, а не заменяла ссылку.
- Атомарная запись: временный файл `.<имя>.opal-tmp` в той же папке →
  запись → `fsync` → права как у исходного файла → `rename` поверх. При
  ошибке временный файл удаляется.
- Перед записью — сравнение текущих `(mtime, size)` с запомненными. Не
  совпали → автосохранение приостановлено, `AlertDialog`: «Загрузить с
  диска» / «Перезаписать». Файл удалён снаружи → создаётся заново.
- Ошибка записи → `AlertDialog` (один раз на серию ошибок), признак `•` в
  заголовке; повтор при следующей правке или `Ctrl+S`.

### 3.8 Обработка ошибок (сводка)

| Ситуация | Реакция |
|---|---|
| Нет конфига | значения по умолчанию |
| Ошибка в строке конфига | предупреждение в stderr, значение по умолчанию |
| Файл не UTF-8 / нет прав на чтение | диалог с ошибкой; документ не открыт (при запуске — пустой документ без имени) |
| Ошибка записи | диалог, `•` в заголовке, повтор позже |
| Внешнее изменение файла | диалог «загрузить / перезаписать» |
| Не открылся url | молча (предупреждение в stderr) |

  - `layout.rs` — узкое/широкое окно, typewriter-поля.

  первого кадра (замер запуска через `time`/`hyperfine`) и вывод времени
  каждого обновления оформления в stderr; память — по RSS процесса.

### 3.10 Прототип и риски

Первая задача плана — прототип с решением «идём дальше / меняем подход»:

1. GtkTextView с захардкоженным текстом: жирный, курсив, заголовок; скрытые
   маркеры с раскрытием под курсором. Проверить: стрелки через скрытый
   текст, клики, выделение, undo не задевается тегами, кириллица.
2. Поля колонки и typewriter-центрирование без циклов перекомпоновки.
3. Замер времени запуска и памяти.

Риски:

- Навигация по `invisible`-тексту в GtkTextView (документация GTK
  предупреждает о багах). Запасной вариант — не скрывать маркеры, а
  показывать бледными (вариант «оформленный исходник»); о переходе на него
  сообщить пользователю.
- Цикл перекомпоновки при смене полей в `size_allocate` — решается
  отложенной установкой полей.
- Время запуска GTK4 зависит от рендерера (GL/Vulkan); если цель 200 мс не
  достигается — замерить с `GSK_RENDERER=cairo` и решить.

### 3.11 Переносимость

Никаких Linux-специфичных API в коде продукта (inotify, `/proc` и т.п.):
только std, GLib/GTK. Открытие ссылок — через `UriLauncher` (портал или
`xdg-open`). Пути конфига — по XDG с запасным `~/.config`.
